# Keyboard transcript actions

The transcript uses one region focus and two reusable action handles per conversation occurrence and session, not one handle per history row. This is a bounded keyboard route, not a full accessibility claim.

- Ctrl+Shift+T enters the most recently focused visible transcript. F6 and Shift+F6 cycle visible conversation occurrences. Hidden tabs are skipped.
- Up/Down select logical visible rows; Home/End select the first/last row. These keys reveal the selected row without running any of its actions.
- Tab/Shift+Tab cycle the row's actions, Jump to latest when present, and the row region. The row copy comes first, followed by fenced-code controls in document order. A closed Mermaid block has Source/Diagram followed by Copy; an unclosed block has only Copy. Enter/Space activate the focused button on release. A row without actions still has the region and optional Jump stop.
- A widget row's controls (Buttons, check boxes, choice options and chips, text fields, sliders) follow the row's actions in that cycle, in the widget's document order, each with a visible focus ring. Enter/Space press a button or tick a box, typing goes to a focused field, and Left/Right move a slider. Tab past the last control returns to the row. Escape leaves from any control; Up/Down/Home/End move between rows except in a text field, where they move the caret. A focused control scrolls into view, and one that scrolls or is pushed out of view returns focus to the row region. The controls are not app-wide tab stops.
- Ctrl+Shift+C copies the focused action's content (the Mermaid source for either diagram control), or the row's first available copy action while the region holds focus. A region without a selected row first selects its visible anchor. Ctrl+C is unchanged. Alt+End focuses Jump to latest without activating it. Escape or Ctrl+L returns to the composer.
- User-message Copy is revealed by row focus as well as hover. Row and button focus have visible outlines. Action focus scrolls its actual button into view, including inside a tall reply.
- Transcript Markdown uses host-managed diagram focus: generic app Tab must not enter a diagram's standalone private tab stops outside the row/action cursor. The component gallery keeps its standalone tab order.
- Replies with selectable text have a final text-selection action after their copy and diagram controls. Its visible outline names the reply text, rather than a separate toolbar button. Ctrl+A selects its rendered text; Shift+arrows extend a range, and Ctrl+C copies only that range. Plain row navigation still applies when there is no range. Escape clears a range before it leaves the transcript. Ctrl+Shift+C retains the full-source copy contract.
- Pointer drags and Shift-click select rendered text across Markdown styles and blocks in one reply. Links open on a click, never on a drag. Lists, quotes, tables and code text participate; Mermaid keeps its separate source controls. Block/cell boundaries copy as newlines. There is no drag autoscroll or selection across separate replies. Append-only streaming retains the selected endpoints; rewritten text clears the range.
- Wheel scrolling retains a nonempty range while its reply remains visible. Scrolling that reply out of view returns focus to the row region; leaving the text surface clears its range. Up/Down use visual text rows, including across code headers and diagrams, while retaining the horizontal goal through wrapped text and tables.
- Reasoning, tool and command rows have named Expand/Collapse controls. Commands keep Copy first in their action order; their disclosure follows it. Reasoning and tools expose their disclosure directly. Enter/Space toggle it, and Ctrl+Shift+C on a disclosure copies its current text. State is transient per conversation occurrence and session, defaults expanded, and is not saved. Empty reasoning remains hidden. Tool rows display the provider's normalized text when available and the item's lifecycle status, not an invented tool result.
- Command disclosures use a compact chevron after Copy, with the full Expand/Collapse name in their tooltip and accessible label, so narrow panes retain space for the command. A command can be collapsed before its output arrives; its later streamed output respects that choice. Tool lifecycle status remains visible beside its disclosure even when its details are collapsed.
- Entry preserves the viewport, including a tall latest reply's bottom. Row movement minimally reveals clipped or offscreen destinations. Send and Jump deliberately clear the old keyboard cursor, so re-entry cannot jump back to an obsolete row. Escape dismisses an open menu or Customize before it leaves the transcript.

Commands and displayed shortcuts come from commands.rs. Composer input, search, Files, Settings, palette and dialogs retain their own key contexts. Enter/Space here do not Send, approve or settle. Settings yields to transcript-entry commands as it does to other workspace commands.
