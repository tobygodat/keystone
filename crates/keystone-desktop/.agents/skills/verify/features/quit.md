# Save and Quit

Ctrl+Q quits every window through the application save transaction, which saves every window's draft and placement in one write. Closing one of several windows closes only that window and leaves its work running (see [windows](windows.md)). Closing the last window uses the same save at once when no turn runs; while a turn runs without waiting for an answer, Keystone keeps running with no window and quits through the same save when it ends. The failure and retry journeys below use Ctrl+Q, or close the last window with nothing running.

## Native acceptance

Use isolated scripted providers and record the exact application SHA and doctor binary hash. Exercise Ctrl+Q with the composer, root, Settings, palette, and a transcript Copy action focused. Exercise title-bar Close and compositor close separately. Type an exact multiline draft immediately before closing, relaunch, and assert both the saved bytes and restored usable editor. Every successful Quit must exit 0, not merely remove its window.

During a scripted turn, record the provider and descendant PIDs, then Quit. They must exit before driver cleanup. Relaunch must show an interrupted turn, with completed log items preserved; partial streamed deltas are not promised recoverable. Repeat while both providers are starting, including version/catalog probes. Never wait for a turn to finish or automatically approve it as part of Quit.

For failure/retry, obstruct the private SQLite database's parent or hold a separate SQLite connection with `BEGIN IMMEDIATE` after history has loaded. `start` returns the live `database` path; the configured `state` path remains the read-only legacy JSON import location. Blocking `sessions` or editing that JSON after import no longer affects writes. Keep a scripted provider active, type a new draft, then Quit. Require the original native window, live app/provider PIDs, exact composer text, and the visible `shutdown-error` element. Open Settings and confirm the same error remains visible there. Repair storage or roll back and close the locking connection, then allow ordinary draft autosave to succeed: the shutdown error must remain sticky. Explicitly retry Quit without another Send, require exit 0 and all owned processes gone, then relaunch and check exact saved draft/log contents without duplicates. Always close the fault-injection connection in a `finally` block before driver cleanup.

GPUI regressions additionally inject directory-sync failure, exercise a nonselected session's failed log/metadata save, count dirty/clean/reentrant saves, cover delayed or stalled history, and verify two independent presentations receive runtime notifications. No-view runtime tests establish app ownership without changing the product's close policy.

For terminal budget loss, launch a debug build with `KEYSTONE_TEST_LOG_BUDGET_BYTES` set to a small budget (release builds ignore it), hold the private SQLite writer lock and send scripted messages until replies are rejected. Require the loss warning before Quit, even for a nonselected session and in Settings. Release the lock and send again: later entries must save without Quit. Then end the app without Quit (SIGKILL), relaunch, and inspect the retained prefix, one Partial “N log entries were lost” report at the place of the first lost entry, and the later messages after it. Retained writes still veto Quit; rejected entries never do. Repeated barriers must not duplicate a marker.

## Limits

A blocked storage syscall can still block shutdown. Forced termination and power loss are best effort; log recovery remains completed-items-only. Cloud software-native receipts do not establish hardware-GPU or real-provider inference behavior.

Rejected budget entries are already discarded, not retryable writes. Quit does not veto that terminal loss alone; only remaining save work can veto. The synced marker makes the gap visible after restart but cannot recover missing content. Terminal log-budget rejection recovery/backpressure is a separate bounded follow-up. The two-second history-load fallback remains: after a vetoed Quit, a history that missed the deadline stays hidden until restart, while new run-tagged entries continue to be saved.
